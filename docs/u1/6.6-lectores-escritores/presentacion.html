Paso 1

El problema, con sleep

Proyecto LeerYEscribir · apartado 6.6

Lo nuevo de hoy

Concepto

Lectores y escritores: hilos con dos papeles que comparten un recurso y no deben estorbarse.

Idea

Dos contadores: un int con los lectores que están dentro y otro con los escritores. Con ellos el fichero sabe si está libre.

Palabra

|| significa «o»: basta con que se cumpla una de las dos condiciones. Es la hermana de && («y»).

Palabra

throws InterruptedException en un método: en vez de un try/catch dentro, deja que el error lo recoja quien llama al método. Aquí, Lector y Escritor.

Idea

El tiempo de leer o escribir (sleep) va fuera de los métodos synchronized, entre la llamada de entrar y la de salir.

Repaso: synchronized, wait(), notifyAll(), Random, sleep() y los arrays de Thread funcionan igual que antes.

Todavía no hay fichero

En este paso no se lee ni se escribe ningún fichero de verdad. Leer y escribir se simula con Thread.sleep(): el hilo se duerme el tiempo que tardaría. Lo importante es coordinar a los hilos. El fichero de verdad llega en el paso 2.

Cómo pensarlo

  • ¿Qué es lo que comparten los siete hilos? El fichero. Será una clase: Fichero.
  • ¿Cómo sabe el fichero si está libre? Cuenta cuántos lectores y cuántos escritores están dentro: int lectores e int escritores.
  • ¿Cuándo tiene que esperar un hilo? Cuando haya algún lector o algún escritor dentro.
  • ¿Quién avisa a los que esperan? El que termina, con notifyAll().

Solución: el fichero

public class Fichero {

    private int lectores = 0;
    private int escritores = 0;

    public synchronized void leerFichero() throws InterruptedException {
        while (lectores > 0 || escritores > 0) {
            System.out.println(Thread.currentThread().getName() + ": Hay alguien usando el fichero. Espero.");
            wait();
        }
        lectores++;
        System.out.println(Thread.currentThread().getName() + ": Leyendo fichero. Lectores: " + lectores);
    }

    public synchronized void escribirFichero() throws InterruptedException {
        while (lectores > 0 || escritores > 0) {
            System.out.println(Thread.currentThread().getName() + ": Hay alguien usando el fichero. Espero.");
            wait();
        }
        escritores++;
        System.out.println(Thread.currentThread().getName() + ": Escribiendo fichero.");
    }

    public synchronized void terminaLeer() {
        lectores--;
        System.out.println(Thread.currentThread().getName() + ": He terminado de leer. Lectores: " + lectores);
        notifyAll();
    }

    public synchronized void terminaEscribir() {
        escritores--;
        System.out.println(Thread.currentThread().getName() + ": He terminado de escribir");
        notifyAll();
    }
}

Línea por línea (1)

  • private int lectores = 0; y private int escritores = 0;
    Cuántos lectores y cuántos escritores están usando el fichero. Empiezan en 0: está libre.
  • public synchronized void leerFichero() throws InterruptedException
    La puerta de entrada del lector. synchronized: solo un hilo a la vez toca los contadores. throws: el error de wait() lo recoge quien llama.
  • while (lectores > 0 || escritores > 0)
    «Mientras haya algún lector o algún escritor…» el hilo no puede entrar.

Línea por línea (2)

  • System.out.println(… "Hay alguien usando el fichero. Espero.")
    Antes de dormirse, el hilo lo dice con su nombre: Thread.currentThread().getName().
  • wait(); (método de la clase Object)
    El hilo se duerme y suelta el fichero, para que el que está dentro pueda terminar.
  • lectores++; y el mensaje Leyendo fichero
    Ya puede leer: se apunta como lector y lo dice, con cuántos lectores hay.

El escritor es casi igual

  • escribirFichero() tiene la misma condición en el while
  • Al entrar suma 1 a escritores y dice Escribiendo fichero.
  • La diferencia entre lector y escritor está en qué contador suma y en qué mensaje muestra

Salir y avisar

  • terminaLeer(): lectores--;, mensaje He terminado de leer y notifyAll();
  • terminaEscribir(): escritores--;, mensaje y notifyAll();
  • notifyAll(); (método de la clase Object): despierta a todos los que esperan. Cada uno vuelve a mirar el while: uno entra y los demás siguen esperando

notifyAll() y notify()

Aquí todos los que esperan esperan lo mismo: que el fichero quede libre. Por eso notify() también funcionaría: el hilo que despierta puede entrar. Pero notifyAll() es la opción segura: sirve aunque los hilos esperen cosas distintas, como el pintor y los vendedores de 6.4. Compruébalo en el simulador.

Solución: el lector

import java.util.Random;

public class Lector implements Runnable {

    private Fichero fich;

    public Lector(Fichero f) {
        this.fich = f;
    }

    private Random r = new Random();

    @Override
    public void run() {
        try {
            fich.leerFichero();
            Thread.sleep((r.nextInt(9) + 2) * 1000);
            fich.terminaLeer();
        } catch (InterruptedException ex) {
        }
    }
}
  • El fichero llega por el constructor y se guarda en fich: es el mismo objeto para todos. Random r da el tiempo al azar
  • Todo va dentro de un try porque leerFichero() declara throws InterruptedException y sleep() también lo exige
  • fich.leerFichero(): si hay alguien, el lector espera aquí. Cuando entra, sigue
  • Thread.sleep(...): leer lleva de 2 a 10 segundos. (r.nextInt(9) + 2) * 1000 da de 2000 a 10000 milisegundos
  • fich.terminaLeer(): sale, lo dice y avisa a los que esperan

Un fallo muy típico: el sleep dentro

Si el sleep estuviera dentro de leerFichero(), el lector seguiría con el fichero bloqueado mientras duerme y los demás ni siquiera podrían entrar a mirar. Por eso leerFichero() y terminaLeer() solo abren y cierran la puerta, y el sleep está en run(), entre las dos llamadas.

Solución: el escritor y los hilos

  • Escritor es igual que Lector, con escribirFichero() y terminaEscribir()
  • Se crea un solo Fichero y se pasa a los siete hilos
  • Los hilos se guardan en dos arrays de Thread: los lectores se arrancan con un for y los escritores con un for-each
Fichero f = new Fichero();
Thread[] lectores = new Thread[5];
lectores[i] = new Thread(new Lector(f), "Lector" + i);
escritores[i] = new Thread(new Escritor(f), "Escritor" + i);
lectores[i].start();
for (Thread escr : escritores) { escr.start(); }

Qué debes ver al ejecutar

  • Un hilo entra y todos los demás dicen Hay alguien usando el fichero. Espero.
  • Cuando el que está dentro termina, entra otro y los demás vuelven a decirlo
  • Lectores: nunca pasa de 1: no hay dos lectores a la vez
  • Nunca sale Escribiendo entre un Leyendo y su He terminado de leer
  • Quién entra primero cambia en cada ejecución. Las reglas, no

Errores típicos

  • El sleep dentro de un método synchronized: los demás ni siquiera pueden entrar a mirar
  • Mirar solo lectores en el while del escritor, o solo escritores en el del lector: entra alguien con el fichero ocupado
  • Usar if en vez de while: al despertar no se vuelve a mirar y se rompe la exclusión
  • Olvidar notifyAll() al terminar: los que esperan no despiertan y el programa no termina
  • Usar notify() sin entender por qué aquí funciona: con hilos que esperan cosas distintas, a veces se cuelga
  • Crear un Fichero por hilo: nadie se espera

Paso 2

El fichero de verdad

Proyecto LectoresFichero

Qué cambia

  • La regla no cambia: un hilo cada vez, mismos contadores, mismo wait() y notifyAll()
  • Cambia lo que hace el hilo cuando ya tiene permiso: en vez de dormir, lee o escribe un fichero de verdad
  • Los escritores escriben su nombre en una línea nueva. Los lectores cuentan las líneas que hay

Ya sabemos coordinar. Ahora vemos cómo se usa el fichero.

Lo nuevo de este paso: los ficheros

Clase

File: representa un fichero del disco por su nombre. No lo abre: solo dice cuál es.

Clase

BufferedReader y FileReader: abren un fichero para leer. El método readLine() lee una línea y devuelve null al llegar al final.

Clase

BufferedWriter y FileWriter: abren un fichero para escribir. write() escribe un texto y newLine() añade el salto de línea.

Método

flush() de BufferedWriter: manda al fichero lo que está en el buffer. Sin él, el texto se queda en memoria y no llega al disco. close() cierra el fichero (y también vacía el buffer).

Escribir un fichero

  • File: representa un fichero del disco. Tiene el nombre, pero todavía no lo abre
  • FileWriter(fichero, true): lo abre para escribir. Con true añade al final; sin él, borra lo que había
  • BufferedWriter: escribe en una memoria intermedia (el buffer) y la manda al disco de golpe. Es más rápido
  • write(texto) escribe; newLine() pasa a la línea siguiente
  • close(): manda el buffer al disco y cierra el fichero. Sin él, el texto puede no llegar al fichero

Leer un fichero

  • FileReader(fichero): lo abre para leer. Si no existe, lanza FileNotFoundException
  • BufferedReader: lee con buffer y permite leer una línea entera
  • readLine(): devuelve la línea siguiente, o null cuando ya no quedan
  • Para contar líneas: while (br.readLine() != null) lineas++;
  • close(): siempre se cierra al terminar

El fichero, ahora de verdad

import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.File;
import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class Fichero {

    private final File fichero;
    private int lectores = 0;
    private int escritores = 0;

    public Fichero(String nombre) throws IOException {
        this.fichero = new File(nombre);
        new FileWriter(fichero).close();
    }

    public synchronized BufferedReader leerFichero() throws InterruptedException, FileNotFoundException {
        while (lectores > 0 || escritores > 0) {
            System.out.println(Thread.currentThread().getName() + ": Hay alguien usando el fichero. Espero.");
            wait();
        }
        lectores++;
        System.out.println(Thread.currentThread().getName() + ": Leyendo fichero. Lectores: " + lectores);
        return new BufferedReader(new FileReader(fichero));
    }

    public synchronized BufferedWriter escribirFichero() throws InterruptedException, IOException {
        while (lectores > 0 || escritores > 0) {
            System.out.println(Thread.currentThread().getName() + ": Hay alguien usando el fichero. Espero.");
            wait();
        }
        escritores++;
        System.out.println(Thread.currentThread().getName() + ": Escribiendo fichero.");
        return new BufferedWriter(new FileWriter(fichero, true));
    }

    public synchronized void terminaLeer() {
        lectores--;
        System.out.println(Thread.currentThread().getName() + ": He terminado de leer. Lectores: " + lectores);
        notifyAll();
    }

    public synchronized void terminaEscribir() {
        escritores--;
        System.out.println(Thread.currentThread().getName() + ": He terminado de escribir");
        notifyAll();
    }
}
  • El constructor crea el fichero vacío: new FileWriter(fichero).close(). Así cada ejecución empieza desde cero
  • leerFichero() y escribirFichero() ya no son void: devuelven el fichero abierto
  • El while, el wait() y los contadores son los mismos de antes

¿Por qué devuelve el fichero y no lo usa dentro?

Si el método synchronized leyera todo el fichero, el lector tendría el fichero bloqueado mientras lee y no pasaría nada raro, pero el método haría dos cosas. Es más claro así: el método solo da permiso y entrega el fichero; el hilo lo usa y después llama a terminaLeer(). La zona protegida es todo el tiempo entre las dos llamadas, no solo el método.

Dos cuidados con el fichero

  • Vaciar el buffer. El BufferedWriter guarda el texto en memoria y lo manda al fichero cuando se llena, o cuando se llama a flush() o close(). Sin flush() el fichero queda vacío y los lectores cuentan 0 líneas
  • Que el fichero exista. Si un lector lo abre antes de que se haya creado, FileReader lanza FileNotFoundException. Como el lector ya había sumado lectores++ y nunca llega a terminaLeer(), el contador se queda en 1 y los escritores esperan para siempre

Por eso el constructor crea el fichero vacío, y por eso el escritor vacía el buffer (con flush() o con close()).

El lector

import java.io.BufferedReader;
import java.io.IOException;

public class Lector implements Runnable {

    private Fichero fich;

    public Lector(Fichero f) {
        this.fich = f;
    }

    @Override
    public void run() {
        try {
            int lineas = 0;
            BufferedReader br = fich.leerFichero();
            while (br.readLine() != null) {
                lineas++;
            }
            br.close();
            System.out.println(Thread.currentThread().getName() + ": He leído " + lineas + " líneas");
            fich.terminaLeer();
        } catch (InterruptedException ex) {
        } catch (IOException ex) {
            System.out.println(ex);
        }
    }
}
  • fich.leerFichero() espera si hace falta y devuelve el BufferedReader
  • Cuenta las líneas, cierra el fichero, lo muestra y después avisa con terminaLeer()
  • IOException: error al leer. Se muestra y ya

El escritor

import java.io.BufferedWriter;
import java.io.IOException;

public class Escritor implements Runnable {

    private Fichero fich;

    public Escritor(Fichero f) {
        this.fich = f;
    }

    @Override
    public void run() {
        try {
            BufferedWriter bw = fich.escribirFichero();
            bw.write(Thread.currentThread().getName());
            bw.newLine();
            bw.close();
            System.out.println(Thread.currentThread().getName() + ": He escrito mi nombre en el fichero");
            fich.terminaEscribir();
        } catch (InterruptedException ex) {
        } catch (IOException ex) {
            System.out.println(ex);
        }
    }
}
  • Pide el fichero, escribe su nombre, close() y avisa de que termina
  • El orden importa: cerrar antes de llamar a terminaEscribir(), para que el siguiente lector vea la línea ya escrita

Principal: ¿quién empieza?

import java.io.IOException;

public class Principal {

    public static void main(String[] args) throws IOException {
        Fichero f = new Fichero("Lectores.txt");

        int numLectores = 5;
        int numEscritores = 2;

        Thread[] lectores = new Thread[numLectores];
        Thread[] escritores = new Thread[numEscritores];

        for (int i = 0; i < numLectores; i++) {
            lectores[i] = new Thread(new Lector(f), "Lector" + i);
        }
        for (int i = 0; i < numEscritores; i++) {
            escritores[i] = new Thread(new Escritor(f), "Escritor" + i);
        }

        for (Thread escr : escritores) {
            escr.start();
        }
        for (int i = 0; i < numLectores; i++) {
            lectores[i].start();
        }
    }
}
  • Se crea Lectores.txt vacío. main declara throws IOException
  • Aquí arrancan primero los escritores. Aun así, un lector puede entrar antes: el número de líneas que cuenta cada lector cambia de una ejecución a otra

Qué debes ver

  • Los mismos mensajes del paso 1, más He leído N líneas
  • Cada lector cuenta 0, 1 o 2 líneas: las que hay en el momento de leer
  • Al terminar, abre Lectores.txt: tiene Escritor0 y Escritor1, cada uno en su línea. Nunca mezclados

Paso 3

Varios lectores a la vez: el semáforo

Proyecto LectoresEscritoresSemaforo · apartado 6.7

Un fallo de eficacia

En los pasos 1 y 2 dos lectores nunca leen a la vez. Pero leer no cambia el fichero: no hay motivo para hacerlos esperar.

Quién entra¿Con quién puede estar?
Un lectorCon otros lectores. No con un escritor
Un escritorCon nadie

Dos contadores ya no bastan. Hace falta recordar en qué estado están los datos.

Una idea para recordarlo

Una sala de lectura con un cartel en la puerta.

  • LIBRE: la sala está vacía. Puede entrar un lector o un escritor
  • CON_LECTORES: hay gente leyendo. Pueden entrar más lectores, pero ningún escritor
  • CON_ESCRITOR: alguien está escribiendo. No entra nadie

El Semaforo es el cartel de la puerta.

Lo nuevo de hoy

Palabra

else if: «si no se cumple lo anterior, prueba esta otra condición».

Idea

Un estado guardado en un int, más un contador de lectores. Con los dos, el semáforo sabe quién puede entrar.

Idea

Un método private que devuelve un texto (info()): una ayuda interna para no repetir el principio de cada mensaje.

Método

random() de la clase Math: da un número al azar entre 0 y 1. Con él, cada hilo duerme un tiempo distinto.

Repaso: synchronized, wait(), notify(), while, sleep(), Runnable y static final funcionan igual que en 6.4, 6.5 y 6.6.

Las reglas: quién puede entrar

Estado del semáforo¿Entra un lector?¿Entra un escritor?
LIBRESíSí
CON_LECTORESSíNo: espera
CON_ESCRITORNo: esperaNo: espera

El estado cambia cuando alguien entra o termina.

Los datos del semáforo

public class Semaforo {

    public static final int LIBRE = 0;
    public static final int CON_LECTORES = 1;
    public static final int CON_ESCRITOR = 2;

    private int estado = LIBRE;
    private int tLectores = 0;
  • LIBRE = 0, CON_LECTORES = 1, CON_ESCRITOR = 2: los tres estados posibles, con nombre para no escribir números sueltos
  • private int estado = LIBRE; en qué estado está ahora. Empieza libre
  • private int tLectores = 0; cuántos lectores están leyendo ahora mismo

¿Por qué constantes y no números?

  • if (estado == 2): ¿qué es 2?
  • if (estado == CON_ESCRITOR): se lee solo
  • static: pertenece a la clase, no a cada objeto. final: no se puede cambiar. Juntos: una constante

Un método auxiliar para los mensajes

    private String info() {
        return "BD:" + estado + " " + tLectores + "L ";
    }
  • private String info(): un método solo para uso interno de la clase. Devuelve un texto, no cambia nada
  • Da el principio de cada mensaje: BD:1 3L (estado 1 y 3 lectores)
  • Así no hay que repetir ese trozo en cada println

accesoLeer(): la puerta del lector

    public synchronized void accesoLeer() {
        String nombre = Thread.currentThread().getName();
        if (estado == LIBRE) {
            System.out.println(info() + nombre + " entra a leer.");
            estado = CON_LECTORES;
        } else if (estado == CON_ESCRITOR) {
            while (estado == CON_ESCRITOR) {
                System.out.println(info() + nombre + " trata de leer. ESPERA");
                try {
                    wait();
                } catch (InterruptedException e) {
                }
            }
            System.out.println(info() + nombre + " entra a leer.");
            estado = CON_LECTORES;
        } else {
            System.out.println(info() + nombre + " entra a leer.");
        }
        tLectores++;
        System.out.println(info() + nombre + " Leyendo.....");
    }

Línea por línea: accesoLeer() (1)

  • public synchronized void accesoLeer()
    Solo un hilo a la vez toca el estado. Es el método que llama un lector antes de leer.
  • String nombre = Thread.currentThread().getName();
    Guarda el nombre del hilo para los mensajes.
  • if (estado == LIBRE)
    Si no hay nadie, el lector entra y cambia el estado a CON_LECTORES.

Línea por línea: accesoLeer() (2)

  • else if (estado == CON_ESCRITOR)
    Si hay un escritor, el lector no puede entrar.
  • while (estado == CON_ESCRITOR) { … wait(); }
    Mientras siga el escritor, el lector avisa («ESPERA») y se duerme. Al despertar vuelve a mirar el estado.
  • Al salir del while, el escritor ya terminó: el lector entra y pone CON_LECTORES.
  • else { … }
    El estado es CON_LECTORES: ya hay lectores. Entra sin esperar y sin cambiar el estado.

Línea por línea: accesoLeer() (3)

  • tLectores++;
    Un lector más leyendo. Se ejecuta siempre, entre por el camino que entre.
  • El último println dice Leyendo..... y enseña el contador

Tres caminos, un único final: sumar 1 a tLectores.

accesoEscribir(): la puerta del escritor

    public synchronized void accesoEscribir() {
        String nombre = Thread.currentThread().getName();
        while (estado != LIBRE) {
            System.out.println(info() + nombre + " trata de escribir. ESPERA");
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        System.out.println(info() + nombre + " entra a escribir.");
        estado = CON_ESCRITOR;
        System.out.println(info() + nombre + " Escribiendo..");
    }
  • while (estado != LIBRE): el escritor espera si hay lectores o escritor: cualquier cosa que no sea libre
  • Al salir, la sala está libre: pone CON_ESCRITOR y escribe solo
  • Comparado con el lector, la condición es más fuerte: el lector solo espera ante un escritor

Terminar: avisar a los que esperan

    public synchronized void escrituraFinalizada() {
        estado = LIBRE;
        System.out.println(Thread.currentThread().getName() + ": Ya ha escrito");
        notify();
    }

    public synchronized void lecturaFinalizada() {
        System.out.println(Thread.currentThread().getName() + ": Ya ha leido");
        tLectores--;
        if (tLectores == 0) {
            estado = LIBRE;
            notify();
        }
    }
  • escrituraFinalizada(): el escritor se va, el estado vuelve a LIBRE y notify() despierta a uno que espera
  • lecturaFinalizada(): un lector menos con tLectores--;
  • if (tLectores == 0): solo el último lector deja el semáforo libre y avisa. Si quedan lectores, no hace falta avisar a nadie

Los hilos: Lector y Escritor

    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + ": Intentando leer");
        semaforo.accesoLeer();
        try {
            Thread.sleep((int) (Math.random() * 500));
        } catch (InterruptedException e) {
        }
        semaforo.lecturaFinalizada();
    }
  • Dice «Intentando leer», pide permiso con accesoLeer() y espera aquí si hace falta
  • sleep(...): el tiempo de lectura, fuera de los métodos synchronized
  • lecturaFinalizada(): avisa de que ha terminado
  • Escritor es igual, con accesoEscribir() y escrituraFinalizada()

Cómo leer cada línea

  • BD:1 el estado en ese momento: 0 libre, 1 con lectores, 2 con escritor
  • 2L cuántos lectores hay dentro
  • Después, el hilo y lo que hace: entra a leer, Leyendo, trata de escribir. ESPERA…
  • Fíjate: varios Leyendo seguidos, con el contador subiendo. Es lo que no pasaba en 6.6

La película, paso a paso

  1. Todos intentan entrar. El primer lector ve LIBRE: entra y el estado pasa a CON_LECTORES
  2. Los demás lectores ven CON_LECTORES: entran sin esperar. tLectores sube
  3. Un escritor llega: el estado no es libre. Dice ESPERA y se duerme con wait()
  4. Los lectores van terminando. El último pone LIBRE y avisa con notify()
  5. El escritor despierta, ve LIBRE, entra y pone CON_ESCRITOR. Al terminar, vuelve a LIBRE y avisa al otro

Un fallo del ejemplo original: el paréntesis

sleep((int) (Math.random()) * 50);    // siempre 0
sleep((int) (Math.random() * 500));   // de 0 a 499
  • Math.random() da un número entre 0 y 1, por ejemplo 0,73
  • En la primera línea, (int) se aplica a 0,73 y da 0. Después se multiplica: 0 × 50 = 0. Nadie duerme
  • En la segunda, primero se multiplica (0,73 × 500 = 365) y después se pasa a int: 365

Sin dormir, casi nadie llega a ver ESPERA. Por eso aquí el paréntesis está corregido.

¿notify() o notifyAll()?

  • Cuando un escritor termina, notify() despierta a uno solo de los que esperan
  • Si despierta a un lector, entra él. Los demás lectores siguen dormidos aunque también podrían entrar
  • Con notifyAll() despertarían todos los lectores a la vez y leerían juntos
  • El programa no se cuelga con notify(): cada vez que el estado vuelve a LIBRE se avisa a otro. Pero es menos eficiente

La discoteca

Proyecto Discoteca · apartado 6.7

Ahora, un ejercicio: la discoteca

  • 5 hilos lectores y 2 hilos escritores comparten el fichero Discoteca.txt
  • Los escritores escriben su nombre en una línea nueva
  • Los lectores cuentan cuántas líneas tiene el fichero en ese momento
  • Varios lectores a la vez, sí. Un escritor, solo

Proyecto Discoteca. Es el mismo problema del semáforo, con un fichero de verdad, pero sin la clase Semaforo: lo resuelves con dos contadores. Ahora lo haces tú.

Cómo pensarlo

  • ¿Qué es lo que comparten los siete hilos? La discoteca, o sea, el fichero. Será una clase: Discoteca.
  • ¿Qué debe recordar? Cuántos lectores hay (lectores) y cuántos escritores (escritores). Sin estado: con los dos contadores basta.
  • ¿Cuándo espera un lector? Solo si hay algún escritor.
  • ¿Cuándo espera un escritor? Si hay algún lector o algún escritor.

Solución: los datos y el constructor

public class Discoteca {

    private final File fichero;
    private int lectores = 0;
    private int escritores = 0;

    public Discoteca(String nombreFichero) throws IOException {
        this.fichero = new File(nombreFichero);
        new FileWriter(fichero).close();
    }
  • private final File fichero; el fichero (final, como en 6.5: se fija en el constructor y no cambia)
  • lectores y escritores: dos contadores, como en el semáforo pero sin estado
  • El constructor recibe el nombre, crea el File y deja el fichero vacío: new FileWriter(fichero).close();

leer(): la puerta del lector

    public synchronized BufferedReader leer() throws InterruptedException, FileNotFoundException {
        while (escritores > 0) {
            System.out.println(Thread.currentThread().getName() + " no puedo leer. Esperando");
            wait();
        }
        lectores++;
        System.out.println(Thread.currentThread().getName() + " entro a leer. Lectores activos: " + lectores);
        return new BufferedReader(new FileReader(fichero));
    }
  • while (escritores > 0): el lector espera solo si hay un escritor. Con otros lectores, entra
  • Entra: lectores++ y mensaje con los lectores activos
  • Devuelve el fichero abierto (BufferedReader). Así el lector lo recorre fuera del método synchronized, sin bloquear a los demás

terminaLeer()

    public synchronized void terminaLeer() {
        lectores--;
        System.out.println(Thread.currentThread().getName() + " termino de leer. Lectores activos: " + lectores);
        if (lectores == 0) {
            notifyAll();
        }
    }
  • Un lector menos, y lo dice
  • if (lectores == 0): solo el último lector avisa. Si quedan lectores, los que esperan (escritores) no pueden entrar todavía

escribir() y terminaEscribir()

    public synchronized BufferedWriter escribir() throws InterruptedException, IOException {
        while (lectores > 0 || escritores > 0) {
            System.out.println(Thread.currentThread().getName() + " no puedo escribir. Esperando");
            wait();
        }
        System.out.println(Thread.currentThread().getName() + " entro a escribir.");
        escritores++;
        return new BufferedWriter(new FileWriter(fichero, true));
    }

    public synchronized void terminaEscribir() {
        System.out.println(Thread.currentThread().getName() + ": He terminado de escribir");
        escritores--;
        notifyAll();
    }
  • while (lectores > 0 || escritores > 0): el escritor espera si hay cualquiera dentro
  • Entra: escritores++ y devuelve un BufferedWriter. true en new FileWriter(fichero, true) significa añadir al final en vez de borrar
  • Al terminar: escritores-- y notifyAll(). Avisa a todos, porque ahora pueden entrar lectores y escritores

Solución: el lector

    public void run() {

            Granada10.terminaLeer();

        } catch (IOException ex) {

  • leer() puede hacer esperar al lector. Cuando entra, recibe el fichero abierto
  • El while con readLine() cuenta las líneas hasta que devuelve null
  • close() cierra el fichero. Después, muestra el resultado y avisa con terminaLeer()
  • Los catch recogen las excepciones de wait() y del fichero

    public void run() {
        try {
            BufferedWriter bw = Granada10.escribir();
            bw.write(Thread.currentThread().getName());
            bw.newLine();
            bw.flush();

        }

  • escribir() hace esperar al escritor hasta que esté solo
  • write() escribe el nombre del hilo y newLine() pasa a la línea siguiente
  • flush() manda al fichero lo escrito: sin él se quedaría en el buffer. Después avisa con terminaEscribir()

Errores típicos

  • Olvidar el tLectores++ en alguno de los tres caminos del lector: el contador no cuadra y el escritor nunca entra
  • Poner estado = LIBRE cada vez que sale un lector, y no solo el último: un escritor entra con lectores leyendo
  • Olvidar el notify() al quedar libre: los que esperan no despiertan y el programa no termina
  • Usar if en vez de while en la espera: al despertar no se vuelve a mirar el estado
  • Un Semaforo (o una Discoteca) por hilo: nadie se espera
  • Olvidar el flush() del escritor: lo escrito no llega al disco y los lectores ven 0 líneas
  • Abrir el fichero antes de que exista: FileNotFoundException y, si el contador no se corrige, los escritores esperan para siempre

Paso 4

La inanición

Proyectos LectoresInanicion y LectoresInanicionResuelta

Un problema que no da error

El semáforo del paso 3 funciona. Pero mira lo que pasa si los lectores no paran de llegar:

  • Un escritor llega y ve CON_LECTORES: espera
  • Antes de que salga el último lector, entra otro lector nuevo
  • Siempre hay algún lector dentro: el estado nunca llega a LIBRE

El escritor no está bloqueado: está esperando su turno, pero los demás se lo van quitando. Eso es la inanición (starvation).

En el ejemplo del semáforo cada hilo lee o escribe una sola vez, y esto no pasa. En un programa real habría que darle prioridad al escritor que espera.

Verlo en Java

public class Principal {

    public static void main(String[] args) throws InterruptedException {
        Semaforo smfro = new Semaforo();

        for (int i = 1; i <= 4; i++) {
            new Thread(new Lector(smfro), "Lector" + i).start();
            Thread.sleep(50);
        }
        new Thread(new Escritor(smfro), "Escritor").start();
    }
}
  • 4 lectores, cada uno lee 6 veces seguidas y vuelve a pedir paso nada más salir
  • Un escritor llega a los 300 ms y quiere escribir una sola vez

Qué sale

Escritor: Intentando escribir
BD:1 4L Escritor trata de escribir. ESPERA
BD:1 4L Lector2 entra a leer.
BD:1 4L Lector3 entra a leer.
… (los lectores siguen entrando) …
BD:0 0L Escritor entra a escribir.

El escritor entra cuando ya han leído los 24 lectores: todos los que llegaron después se le colaron.

Aquí termina porque los lectores son finitos. Con lectores sin fin, no escribiría nunca.

La idea de la solución

  • El semáforo tiene que acordarse de que hay un escritor esperando
  • Un contador nuevo: escritoresEsperando
  • El escritor se apunta antes de esperar y se borra cuando entra
  • Un lector nuevo espera si hay un escritor escribiendo o esperando
  • Los lectores que ya están dentro terminan. El último deja LIBRE y el escritor entra

Es como una cola: el que llega primero no se queda atrás.

Sin inanición: el contador nuevo

    public static final int LIBRE = 0;
    public static final int CON_LECTORES = 1;
    public static final int CON_ESCRITOR = 2;

    private int estado = LIBRE;
    private int tLectores = 0;
    private int escritoresEsperando = 0;

Todo lo demás está igual que en el paso 3. Solo se añade escritoresEsperando.

Sin inanición: entra un lector

    public synchronized void accesoLeer() {
        String nombre = Thread.currentThread().getName();
        while (estado == CON_ESCRITOR || escritoresEsperando > 0) {
            System.out.println(info() + nombre + " trata de leer. ESPERA");
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        System.out.println(info() + nombre + " entra a leer.");
        estado = CON_LECTORES;
        tLectores++;
    }
  • El lector espera si hay un escritor escribiendo o esperando

Sin inanición: entra un escritor

    public synchronized void accesoEscribir() {
        String nombre = Thread.currentThread().getName();
        escritoresEsperando++;
        while (estado != LIBRE) {
            System.out.println(info() + nombre + " trata de escribir. ESPERA");
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        escritoresEsperando--;
        System.out.println(info() + nombre + " entra a escribir.");
        estado = CON_ESCRITOR;
        System.out.println(info() + nombre + " Escribiendo..");
    }
  • Se apunta antes de esperar y se borra al entrar

Sin inanición: las salidas

    public synchronized void escrituraFinalizada() {
        estado = LIBRE;
        System.out.println(Thread.currentThread().getName() + ": Ya ha escrito");
        notifyAll();
    }

    public synchronized void lecturaFinalizada() {
        tLectores--;
        if (tLectores == 0) {
            estado = LIBRE;
            notifyAll();
        }
    }
  • Las dos terminan con notifyAll()

Línea por línea

  • escritoresEsperando: cuántos escritores esperan su turno
  • accesoLeer(): while (estado == CON_ESCRITOR || escritoresEsperando > 0). Ahora el lector espera aunque el estado sea CON_LECTORES, si hay un escritor esperando
  • accesoEscribir(): escritoresEsperando++ antes del while. Cuando sale del while, escritoresEsperando--
  • El if/else if de antes se cambia por un solo while: más corto y hace lo mismo

Y ahora notifyAll()

En el paso 3 bastaba notify(). Aquí no: si notify() despertara a un lector, este vería que hay un escritor esperando y se volvería a dormir. El aviso se perdería y el escritor seguiría dormido. Con notifyAll() despiertan todos y el escritor puede entrar. Compruébalo en el simulador: con notify() el programa a veces se cuelga.

Qué debes ver

  • El escritor dice ESPERA y, a partir de ahí, los lectores nuevos también
  • Los lectores que estaban dentro terminan su lectura (BD:1 con cada vez menos lectores)
  • Entra el escritor (BD:2) y, cuando termina, siguen los lectores
  • Entra tras unas 10 lecturas, no tras las 24

Probarlo en el simulador

  • Un contador muestra los lectores que han entrado con un escritor esperando. En el semáforo de 6.7 sube; con la solución se queda en 0
  • Prueba a olvidar escritoresEsperando-- y mira qué pasa

Problemas de sincronización

PSP · 2º DAM · Apartado 6.6

Objetivo de la clase

  • Resolver cuatro problemas con hilos que comparten un objeto
  • Reconocer el patrón que se repite en todos
  • Simular tiempo con el método sleep() de la clase Thread y azar con la clase Random
  • Esperar a que terminen varios hilos con el método join() de la clase Thread
  • Leer del teclado con Scanner

El patrón de los cuatro ejercicios

  1. Hay un objeto compartido (cinta, lavandería, mostrador…)
  2. Sus métodos son synchronized
  3. Si el hilo no puede continuar: while (no puedo) wait();
  4. Cuando cambia el estado: notifyAll();
  5. Los hilos solo duermen, llaman al objeto y repiten

Entiende uno y entiendes los cuatro.

Lo nuevo de hoy

Método

sleep(ms) de la clase Thread: duerme el hilo esos milisegundos (2000 = 2 segundos). Simula que algo tarda.

Clase

Random: nextInt(3) da al azar 0, 1 o 2.

Método

join() de la clase Thread: «espero aquí hasta que ese hilo termine».

Clase

Scanner: nextInt() lee un número que escribe el usuario.

Clase

ArrayList: una lista que crece sola.

Regla: sleep va fuera de synchronized. Si un hilo duerme dentro, los demás no pueden ni entrar.

Ejercicio 1: fábrica de piezas

  • 3 máquinas creadoras ponen piezas en una cinta de capacidad 5. Una pieza cada 2–3 s
  • 1 máquina empaquetadora retira una pieza cada segundo
  • Cinta llena: las creadoras esperan. Cinta vacía: la empaquetadora espera
  • Se crean 50 piezas entre todas. Se muestra «Fábrica cerrada»
  • Las máquinas no saben cuántas piezas habrá: lo sabe la cinta

Proyecto FabricaPiezas

Cómo pensarlo

  • Es el pintor y el vendedor otra vez, pero con tres productores → notifyAll()
  • El límite de 50 es de todas las máquinas juntas → el contador está en la CintaTransportadora, no en cada máquina
  • ¿Cómo sabe una máquina que debe parar? → el método de la cinta le devuelve false
  • ¿Cómo sabe la empaquetadora que ya no habrá más? → la cinta le avisa con una bandera

El método de resolución: dos banderas

Una bandera es un boolean que dice «sigue» o «para».

  • seguirFabricando: empieza en true. Pasa a false cuando ya se han creado las 50
  • seguirEmpaquetando: empieza en true. Pasa a false cuando la cinta está vacía y ya no se fabrica
  • Cada método de la cinta devuelve su bandera, y la máquina repite while (cinta.metodo())

La máquina no cuenta nada: pregunta a la cinta si debe seguir.

Lo nuevo de este ejercicio

Palabra

static final: una constante de la clase. Su valor no cambia y se escribe en MAYÚSCULAS (CAPACIDAD).

Palabra

final en una variable: su valor no se puede cambiar (final int numCreadoras = 3;).

Idea

Un método synchronized que devuelve boolean: la máquina repite mientras devuelva true. Es la señal de fin de 6.4, pero con banderas.

Palabra

throws InterruptedException en un método: deja que el error de wait() lo recoja quien lo llama (aquí, la máquina).

Solución: los datos de la cinta

public class CintaTransportadora {

    private static final int CAPACIDAD = 5;
    private static final int TOTAL_PIEZAS = 50;

    private int piezasCinta = 0;
    private int piezasCreadas = 0;
    private int piezasEmpaquetadas = 0;
    private boolean seguirFabricando = true;
    private boolean seguirEmpaquetando = true;
  • CAPACIDAD y TOTAL_PIEZAS: dos constantes. Para cambiar la fábrica, solo se cambian aquí
  • Tres contadores: las piezas que hay en la cinta, las creadas y las empaquetadas
  • Dos banderas, las dos en true: al empezar hay que fabricar y empaquetar

crearPieza(): la puerta de la creadora

    public synchronized boolean crearPieza() throws InterruptedException {
        while (piezasCinta == CAPACIDAD) {
            System.out.println("No puedo crear piezas. Cinta llena: " + piezasCinta + ".");
            wait();
        }
        if (piezasCreadas >= TOTAL_PIEZAS) {
            seguirFabricando = false;
        } else {
            piezasCinta++;
            piezasCreadas++;
            System.out.println("Pieza creada. Total en cinta: " + piezasCinta + ". Creadas: " + piezasCreadas);
        }
        notifyAll();
        return seguirFabricando;
    }

Línea por línea: crearPieza()

  • while (piezasCinta == CAPACIDAD): la cinta está llena. La máquina lo dice y se duerme con wait(). Al despertar vuelve a mirar
  • if (piezasCreadas >= TOTAL_PIEZAS): ya se crearon todas. seguirFabricando = false; y no se crea nada
  • else { piezasCinta++; piezasCreadas++; … }: una pieza más en la cinta y una más creada
  • notifyAll();: avisa a todos. La empaquetadora ya puede retirar, o puede que ya no haya que fabricar
  • return seguirFabricando;: true mientras haya que seguir y false la primera vez que se descubre que ya está todo

empaquetar(): la puerta de la empaquetadora

    public synchronized boolean empaquetar() throws InterruptedException {
        while (piezasCinta == 0 && seguirFabricando) {
            System.out.println("No puedo empaquetar piezas. Cinta vacía: " + piezasCinta + ".");
            wait();
        }
        if (piezasCinta == 0 && !seguirFabricando) {
            seguirEmpaquetando = false;
        } else {
            piezasCinta--;
            piezasEmpaquetadas++;
            System.out.println("Pieza empaquetada. Total en cinta: " + piezasCinta + ". Empaquetadas: " + piezasEmpaquetadas);
            notifyAll();
        }
        return seguirEmpaquetando;
    }
  • while (piezasCinta == 0 && seguirFabricando): espera si está vacía y todavía se crean piezas
  • if (piezasCinta == 0 && !seguirFabricando): vacía y no se crea más: seguirEmpaquetando = false;. ! = «no»
  • Si no, hay una pieza: se retira, se cuenta y se avisa

Cómo termina todo: la película del final

  1. Se crea la pieza 50. piezasCreadas vale 50 y la creadora duerme sus 2–3 s
  2. Al despertar, cada creadora vuelve a llamar a crearPieza(). La primera ve piezasCreadas >= TOTAL_PIEZAS y pone seguirFabricando = false
  3. Ese método llama a notifyAll(): despierta a la empaquetadora, si esperaba con la cinta vacía
  4. Las creadoras reciben false y terminan
  5. La empaquetadora retira las piezas que queden. Con la cinta vacía y seguirFabricando a false, pone seguirEmpaquetando = false y recibe false: termina
  6. main ya puede pasar los join() y mostrar «Fábrica cerrada»

¿Por qué dos banderas y no una?

  • Las creadoras terminan cuando ya no hay que crear
  • La empaquetadora no puede terminar a la vez: todavía puede haber piezas en la cinta
  • Por eso la empaquetadora termina cuando la cinta está vacía y ya no se crea más

Dos papeles, dos finales: una bandera por papel.

Las máquinas

    @Override
    public void run() {
        try {
            while (cinta.crearPieza()) {
                Thread.sleep(rand.nextInt(1000) + 2000);
            }
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
  • while (cinta.crearPieza()): repite mientras la cinta diga true. La máquina no sabe cuántas piezas hay
  • nextInt(1000) + 2000: el método nextInt() de la clase Random da de 0 a 999. Con 2000 más: 2 a 3 segundos. El Random es static final: uno solo para todas
  • El sleep está fuera de crearPieza(): si no, nadie más usaría la cinta mientras una máquina duerme
  • MaquinaEmpaquetadora es igual, con empaquetar() y sleep(1000)

Crear y esperar a todos los hilos


final int numCreadoras = 3;
Thread[] maquinasCreadoras = new Thread[numCreadoras];

maquinasCreadoras[i] = new Thread(new MaquinaCreadora(cinta), "Creadora" + i);

for (Thread hilo : maquinasCreadoras) { hilo.start(); }

System.out.println("Fábrica cerrada");
  • Los hilos se guardan en un array de Thread, y se recorre con un for sencillo (for-each)
  • Lo mismo con las empaquetadoras. Cambiar numCreadoras cambia cuántas hay
  • El método join() de la clase Thread: «espero a que este hilo termine». Sin los join(), «Fábrica cerrada» saldría al principio
  • main declara throws InterruptedException para no escribir un try/catch en cada join

Ejercicio 2: lavandería CleanFast

  • 4 lavadoras. Cada cliente lava de 10 a 20 segundos y paga 3 €
  • Sin lavadora libre, el cliente espera. Solo cuenta como atendido cuando consigue una
  • Menú: 1) llegan clientes, 2) estado, 3) cerrar (espera a que terminen todos)
  • Los clientes pueden llegar en varias tandas: los nombres no se repiten

Proyecto Lavanderia

Lo nuevo de este ejercicio

Palabra

do { … } while (condición);: repite el bloque y mira la condición al final. Siempre se ejecuta al menos una vez: ideal para un menú.

Interfaz

List<Thread>: «una lista de hilos». ArrayList es la lista concreta que se crea con new.

Operador

+=: suma a la variable lo de la derecha. dineroGanado += PRECIO; es dineroGanado = dineroGanado + PRECIO;.

Palabra

throws Exception: main deja pasar cualquier error, sin try/catch.

Cómo pensarlo

  • ¿Hace falta una clase por lavadora? No: solo importa cuántas hay libres.
  • Es el almacén de un cuadro, pero con 4 huecos en vez de 1
  • ¿Dónde cuento al cliente como atendido y cobro? Justo después del while, cuando ya tiene lavadora.
  • ¿Qué hilos esperan a la vez? Solo clientes, y todos esperan lo mismo: una lavadora libre.

Solución: los datos de la lavandería

public class Lavanderia {

    public final int LAVADORAS = 4;
    private final int PRECIO = 3;
    private int lavadorasDisponibles = LAVADORAS;
    private int clientesAtendidos = 0;
    private int dineroGanado = 0;
  • LAVADORAS y PRECIO: dos constantes final. Para cambiar la lavandería, solo se cambian aquí
  • lavadorasDisponibles empieza igual que LAVADORAS: todas libres
  • clientesAtendidos y dineroGanado: dos contadores para el estado

ponerLavadora() y quitarLavadora()

    public synchronized void ponerLavadora() throws InterruptedException {
        while (lavadorasDisponibles == 0) {
            System.out.println(Thread.currentThread().getName() + " esperando. No hay lavadoras disponibles.");
            wait();
        }
        lavadorasDisponibles--;
        dineroGanado += PRECIO;
        clientesAtendidos++;
        System.out.println(Thread.currentThread().getName() + " pone una lavadora. Lavadoras disponibles: " + lavadorasDisponibles);
    }

    public synchronized void quitarLavadora() {
        lavadorasDisponibles++;
        System.out.println(Thread.currentThread().getName() + " terminó de lavar. Lavadoras disponibles: " + lavadorasDisponibles);
        notify();
    }
  • while (lavadorasDisponibles == 0): el cliente lo dice y se duerme con wait(). Al despertar, vuelve a mirar
  • Al salir del while ya tiene lavadora: resta una, cobra y cuenta al cliente
  • Al terminar, quitarLavadora() suma una lavadora y llama a notify()

¿notify() o notifyAll()?

Aquí vale notify(): todos los que esperan son clientes y esperan lo mismo (una lavadora libre). Despertar a uno cualquiera basta, y ese puede coger la lavadora.

Con papeles distintos, como el pintor y los vendedores de 6.4, notify() podría despertar al equivocado. Si dudas, notifyAll() es la opción segura.

El estado: mostrarInfo()

    public synchronized void mostrarInfo() {
        System.out.println("Estado de la lavandería:\n\tClientes totales: " + clientesAtendidos
                + "\n\tDinero ganado: " + dineroGanado + "€"
                + "\n\tLavadoras disponibles: " + lavadorasDisponibles
                + "\n\tLavadoras alquiladas: " + (LAVADORAS - lavadorasDisponibles));
    }
  • \n es un salto de línea y \t un tabulador, dentro de un texto
  • «Alquiladas» = las que están en uso: LAVADORAS - lavadorasDisponibles
  • También es synchronized: la lectura no se mezcla con un cliente que está cogiendo o dejando una lavadora

El cliente

    @Override
    public void run() {
        try {
            cleanFast.ponerLavadora();
            int tiempoUso = 10 + random.nextInt(11);
            Thread.sleep(tiempoUso * 1000);
            cleanFast.quitarLavadora();
        } catch (InterruptedException ex) {
        }
    }
  • ponerLavadora() puede hacer esperar al cliente. Cuando sigue, ya tiene lavadora
  • 10 + random.nextInt(11): el método nextInt() de la clase Random da de 0 a 10, y con 10 más sale de 10 a 20 segundos
  • El sleep está fuera de los métodos de la lavandería: las otras lavadoras siguen trabajando
  • quitarLavadora(): deja la lavadora libre

El menú: do while y switch

        do {
            menu = sc.nextInt();

            switch (menu) {
                case 1:
                    System.out.println("¿Cuántos clientes llegan a la vez?");
                    numClientes = contador + sc.nextInt();
  • do { … } while (menu != 3): el menú se repite hasta que se elige cerrar
  • switch (menu): elige qué hacer según la opción. Cada case acaba en break
  • En la opción 1: numClientes = contador + sc.nextInt();. Suma los que llegan a los que ya habían llegado

Los clientes llegan en varias tandas

                    numClientes = contador + sc.nextInt();
                    for (int i = contador; i < numClientes; i++, contador++) {
                        Hilos.add(new Thread(new Cliente(CleanFast), "Cliente " + (contador + 1)));
                        Hilos.get(contador).start();
                    }

  • contador: cuántos clientes han llegado en total
  • El for empieza en contador, no en 0: así el segundo grupo sigue donde acabó el primero
  • i++, contador++: las dos suben a la vez. contador da nombre al cliente (Cliente 1, Cliente 2…) y es la posición del hilo en la lista
  • Hilos.add(...) lo guarda y Hilos.get(contador).start() lo arranca

Cerrar: esperar a todos

                case 3:
                    System.out.println("Cerramos tienda. Esperamos a que terminen de lavar");
                    for (Thread hilo : Hilos) {
                        hilo.join();
                    }
                    break;
  • Se muestra el mensaje y main recorre la lista con un for-each
  • hilo.join(): «espero a que este cliente termine». Así se espera a los que estaban lavando y a los que esperaban lavadora
  • Después, menu vale 3 y el do while acaba: el programa termina

El menú solo se muestra una vez, al principio. Si lo quieres ver en cada vuelta, el println iría dentro del do.

Ejercicio 3: panadería self-service

  • 20 barras al abrir. Cada segundo el panadero mira: si quedan menos de 10, hornea 20 (tarda 20 s)
  • Cada cliente pide de 1 a 10 barras. Si no hay suficientes, espera
  • Primera barra 1 €, las demás 0,75 €
  • Menú: 1) grupo de clientes, 2) estado, 3) cerrar
  • Al cerrar: el panadero se lleva lo que queda y hornea un último lote

Proyecto Panaderia

Cómo pensarlo

  • ¿Quién comparte qué? Panadero y clientes comparten la Panaderia.
  • Hornear tarda 20 s. ¿Dentro de synchronized? No: los clientes no podrían comprar mientras tanto.
  • ¿Cuándo se cierra? Cuando todos los clientes han terminado. Algunos aún esperan pan: el panadero tiene que seguir horneando.

Solución: la panadería

    private int barrasDisponibles = 20;
    private int barrasVendidas = 0;
    private int totalBarrasHorneadas = 20;
    private double dineroGanado = 0;
    private boolean abierta = true;

    public synchronized void atenderCliente(int barrasSolicitadas) throws InterruptedException {
        while (barrasDisponibles < barrasSolicitadas) {
            System.out.println(Thread.currentThread().getName() + " esperando. No hay suficiente pan.");
            wait();
        }
        double precio = 1.0 + (barrasSolicitadas - 1) * 0.75;
        dineroGanado += precio;
        barrasDisponibles -= barrasSolicitadas;
        barrasVendidas += barrasSolicitadas;
        System.out.println(Thread.currentThread().getName() + " compró " + barrasSolicitadas + " barras por " + precio + "€. Barras restantes: " + barrasDisponibles);
    }

Línea por línea

  • double dineroGanado: double es un número con decimales
  • totalBarrasHorneadas empieza en 20: el texto cuenta las 20 barras iniciales
  • while (barrasDisponibles < barrasSolicitadas): el cliente espera hasta que haya tantas como pide, no solo «alguna»
  • 1.0 + (barrasSolicitadas - 1) * 0.75: la primera barra 1 €, las demás 0,75 €. Con 3 barras: 1 + 0,75 × 2 = 2,50 €
  • reponer(20): método de la clase Panaderia. Suma las barras y llama a notifyAll(). Los clientes dormidos vuelven a mirar si ya hay suficientes

El panadero

    public void run() {
        try {
            while (panaderia.estaAbierta()) {
                Thread.sleep(1000);
                if (panaderia.estaAbierta() && panaderia.hacenFaltaBarras()) {
                    panaderia.hornear();
                }
            }
            panaderia.llevarseBarras();
            panaderia.hornear();
        } catch (InterruptedException e) {
        }
    }

Hornear: método de Panaderia

        barrasDisponibles += barras;
        totalBarrasHorneadas += barras;
        System.out.println("Panadero terminó de hornear. Barras disponibles: " + barrasDisponibles);
        notifyAll();
    }
  • hornear() está en Panaderia como el resto de métodos. El panadero solo escribe panaderia.hornear(), así no se repiten las mismas líneas
  • No es synchronized, pero reponer sí
  • Se hornea con Thread.sleep(20000) sin tener la panadería «cogida»: durante esos 20 segundos los clientes pueden seguir comprando

Cerrar la panadería

  1. Salir del menú. No se aceptan más clientes
  2. join() a todos los clientes: los que esperan pan se atienden
  3. panaderia.cerrarPanaderia(): método de la clase Panaderia. Avisa al panadero
  4. El panadero sale de su bucle, se lleva lo que queda y hornea el último lote
  5. join() al panadero y resumen final

El orden importa. Si se avisara al panadero antes, vaciaría el mostrador y los clientes que esperan se quedarían colgados.

Lanzar un grupo de clientes

                        System.out.print("¿Cuántas barras quiere el cliente " + clienteId + " (1-10)? ");
                        int barras = sc.nextInt();
                        while (barras < 1 || barras > 10) {
                            System.out.println("Número de barras no válido. Deben ser entre 1 y 10.");
                            barras = sc.nextInt();
                        }
                        grupo.add(new Thread(new Cliente(panaderia, barras), "Cliente" + clienteId));
                        clienteId++;
                    }
                    for (Thread cliente : grupo) {
                        clientes.add(cliente);
                        cliente.start();
                    }
                    break;
                case 2:
                    panaderia.mostrarInfo();
  • List<Thread> es una lista de hilos. A diferencia de un array, no tiene tamaño fijo: no sabemos cuántos clientes llegarán, y con add sigue creciendo
  • new Cliente(panaderia, barras): el Cliente guarda la panadería compartida y las barras que pide. Aún no hace nada
  • new Thread(cliente, "Cliente" + clienteId): el hilo recibe el trabajo (el run() del cliente) y un nombre, que es el que sale al imprimir
  • start(): aquí arranca de verdad. Todos los clientes reciben el mismo objeto panaderia: por eso compiten por la misma llave

¿Para qué guardamos los hilos en la lista?

  • Para poder hacer join() a cada uno al cerrar: «espero aquí hasta que este hilo termine»
  • El programa no se colgaría sin join. Lo que importa es el orden

Sin join, cerrarPanaderia() se ejecutaría enseguida: los clientes que aún esperan pan se quedarían sin panadero, y el resumen saldría con cifras incompletas.

cerrarPanaderia() solo baja una bandera (abierta = false). Quien reacciona es el panadero, que la mira cada segundo y entonces se lleva el pan y hornea el último lote. Por eso main hace join al panadero antes del resumen.

Todas las cuentas viven en la panadería

  • Barras disponibles, vendidas, horneadas, dinero y si está abierta: todo en Panaderia, todo private
  • Clientes y panadero no guardan nada compartido: solo llaman a métodos de la panadería
  • Así hay una sola cuenta y un solo sitio que proteger con synchronized
  • Solo Cliente guarda barrasSolicitadas: es un dato suyo, que nadie más toca

Un fallo típico: hornear dentro de synchronized

Si hornear() fuera un método synchronized de la panadería y durmiera los 20 segundos dentro, nadie podría comprar ni mirar el estado mientras tanto: el panadero tiene la panadería «cogida».

Por eso hornear() no es synchronized y solo reponer coge la panadería, un instante.

Tampoco sería un error dejar las ventas paradas mientras se hornea: el resultado sería correcto. Pero el enunciado dice que el cliente espera «hasta que el panadero haya horneado más», lo que solo tiene sentido si los demás pueden seguir comprando.

Ejercicio 4: sala de partida de stream

  • Jugadores: solo uno en directo, y no entra si quedan espectadores dentro. Los demás esperan
  • Espectadores: entran todos los que quieran, pero solo si hay un jugador en directo. Si no, esperan
  • Se quedan un tiempo o hasta que acaba el jugador, descansan y repiten. Cada vuelta tienen 1 posibilidad entre 10 de irse
  • Menú: 1) jugador, 2) espectadores, 3) estado, 4) salir

Proyecto Streamer

Dos grupos esperando cosas distintas

  • El jugador espera a que no haya nadie dentro
  • El espectador espera a que sí haya un jugador en directo

Los dos esperan sobre el mismo objeto, Sala. Por eso notifyAll(): cada uno se despierta, mira su condición y, si no es su momento, se vuelve a dormir.

Lo nuevo de este ejercicio

Método

wait(milisegundos): como wait(), pero se despierta solo cuando pasa ese tiempo. Si alguien llama antes a notifyAll(), se despierta antes. Mientras espera, la sala queda libre.

Con wait(tiempo) el espectador está dentro ese tiempo o hasta que el jugador sale: el notifyAll() de SaleJugador() lo despierta.

Solución: la sala y el jugador

    private int numEspectadores = 0;
    private boolean enDirecto = false;
    private String jugadorEnDirecto = "";

    public synchronized void EntraJugador(int tiempo) throws InterruptedException {
        while (enDirecto || numEspectadores > 0) {
            System.out.println(Thread.currentThread().getName() + ": No puedo entrar a la sala, me toca esperar.");
            wait();
        }
        System.out.println(Thread.currentThread().getName() + ": Jugando durante " + (tiempo / 1000) + " segundos");
        enDirecto = true;
        jugadorEnDirecto = Thread.currentThread().getName();
    }
  • El jugador espera mientras haya alguien en directo o espectadores dentro
  • Al entrar, marca que está en directo y guarda su nombre

El jugador sale

    public synchronized void SaleJugador() {
        jugadorEnDirecto = "";
        enDirecto = false;
        System.out.println("Soy " + Thread.currentThread().getName() + " abandono la sala");
        notifyAll();
    }
  • notifyAll() despierta a los espectadores (para que salgan) y a los jugadores en cola

Los espectadores: entrar

    public synchronized void EntraEspectador(int tiempo) throws InterruptedException {
        while (!enDirecto) {
            System.out.println(Thread.currentThread().getName() + ": Sala vacía, espero a que se conecte un jugador.");
            wait(15000);
        }
        numEspectadores++;
        System.out.println("Soy " + Thread.currentThread().getName() + " entro durante " + (tiempo / 1000) + " seg, actualizo estado sala: " + getInfoSala());
        wait(tiempo);
    }
  • wait(15000): si no hay jugador, vuelve a mirar cada 15 segundos y lo muestra
  • Al entrar suma un espectador y espera wait(tiempo): ese tiempo o hasta que el jugador salga

Los espectadores: salir

    public synchronized void SaleEspectador() throws InterruptedException {
        numEspectadores--;
        if (numEspectadores == 0) {
            notifyAll();
        }
        System.out.println("Soy " + Thread.currentThread().getName() + " salgo, actualizo estado sala: " + getInfoSala());
    }
  • El último espectador en salir avisa con notifyAll(): ahora puede entrar un jugador
  • Si no avisara, el jugador en cola se quedaría esperando para siempre

¿Qué sale en pantalla?

Ejercicio 5: cerrar la sala

  • La opción 4 cierra la sala: Sala cerrada. Vayan saliendo de forma ordenada.
  • Los jugadores en cola no juegan y los espectadores dejan de volver
  • ¿Terminan todos los hilos? Pruébalo con espectadores que esperan a un jugador que ya no vendrá

Proyecto Streamer2

Cerrar: qué cambia

    public synchronized boolean EntraJugador(int tiempo) throws InterruptedException {
        while (enDirecto || numEspectadores > 0) {
            System.out.println(Thread.currentThread().getName() + ": No puedo entrar a la sala, me toca esperar.");
            wait();
        }
        if (!salaCerrada) {
            System.out.println(Thread.currentThread().getName() + ": Jugando durante " + (tiempo / 1000) + " segundos");
            enDirecto = true;
            jugadorEnDirecto = Thread.currentThread().getName();
        }
        return enDirecto;
    }
  • EntraJugador() ahora devuelve un boolean: true si ha podido jugar y false si la sala se cerró mientras esperaba

Cerrar la sala

    public synchronized boolean getSalaCerrada() {
        return salaCerrada;
    }

    public synchronized void cerrarSala() {
        salaCerrada = true;
        System.out.println("Sala cerrada. Vayan saliendo de forma ordenada.");
        notifyAll();
    }
  • cerrarSala() marca la sala como cerrada y llama a notifyAll(): los jugadores que esperaban vuelven a mirar, ven la sala cerrada y se van
  • El espectador repite mientras la sala no esté cerrada

¿Terminan todos?

Cierra la sala cuando haya espectadores esperando y ningún jugador en directo.

Esos espectadores están en while (!enDirecto). Nadie les dice que la sala está cerrada: siguen esperando a un jugador que no va a llegar y el programa no termina.

Se arregla en el siguiente ejercicio: la condición de espera debe mirar también si la sala está cerrada.

Ejercicio 6: sleep fuera y cerradura propia

  • El espectador entra, se queda y sale dentro de un solo método
  • El tiempo dentro se espera con Thread.sleep(), fuera de synchronized
  • La sala sincroniza sobre un objeto propio, lock
  • La sala cerrada no deja a nadie esperando para siempre

Proyecto Streamer3

Lo nuevo de este ejercicio

Concepto

Object lock = new Object();: un objeto cualquiera que se usa solo como cerradura.

Palabra

synchronized (lock) { … }: el hilo coge la cerradura solo mientras dura el bloque. Dentro se escribe lock.wait() y lock.notifyAll().

Todos los métodos de la sala deben usar la misma cerradura.

El espectador: tres partes

    public void EntraSaleEspectador(int tiempo) throws InterruptedException {
        synchronized (lock) {
            while (!enDirecto && !salaCerrada) {
                System.out.println(Thread.currentThread().getName() + ": Sala vacía, espero a que se conecte un jugador.");
                lock.wait(15000);
            }
            if (!enDirecto) {
                return;
            }
            numEspectadores++;
            System.out.println("Soy " + Thread.currentThread().getName() + " entro durante " + (tiempo / 1000) + " seg, actualizo estado sala: " + getInfoSala());
        }

        Thread.sleep(tiempo);

        synchronized (lock) {
            numEspectadores--;
            if (numEspectadores == 0) {
                lock.notifyAll();
            }
            System.out.println("Soy " + Thread.currentThread().getName() + " salgo, actualizo estado sala: " + getInfoSala());
        }

        Thread.sleep(tiempo);
    }
  • Primer bloque: espera a un jugador (o a que se cierre la sala) y entra
  • Thread.sleep(tiempo) fuera del bloque: mientras está dentro, los demás pueden usar la sala
  • Segundo bloque: sale, y si es el último avisa con lock.notifyAll()
  • Después descansa otro rato

Lo que cambia con sleep

sleep no se despierta con notifyAll(). El espectador ya no sale cuando acaba el jugador, sino cuando acaba su tiempo.

Por eso el jugador siguiente espera a que salga el último espectador. Es lo que ya hacía numEspectadores > 0 en su while.

Cerrar con la misma cerradura

    public boolean getSalaCerrada() {
        synchronized (lock) {
            return salaCerrada;
        }
    }

    public void cerrarSala() {
        synchronized (lock) {
            salaCerrada = true;
            System.out.println("Sala cerrada. Vayan saliendo de forma ordenada.");
            lock.notifyAll();
        }
    }
  • getSalaCerrada() y cerrarSala() también usan synchronized (lock) y lock.notifyAll()
  • El espectador que espera un jugador sale si la sala se cierra: while (!enDirecto && !salaCerrada)

Si cerrarSala() fuera synchronized sobre la sala, su notifyAll() avisaría a quienes esperan sobre la sala. Nadie espera ahí: todos esperan sobre lock. No despertaría a nadie.

Errores típicos

  • Thread.sleep() dentro de un método synchronized: nadie más puede avanzar
  • notify() en vez de notifyAll(): a veces funciona y a veces se cuelga
  • if en vez de while alrededor de wait()
  • Un objeto compartido por hilo: ya no se comparte nada
  • Olvidar los join(): el mensaje final sale al principio
  • Contar el límite en cada hilo en vez de en el objeto compartido
  • Sincronizar unos métodos sobre la sala y otros sobre otro objeto: el notifyAll() no despierta a nadie
  • No mirar si la sala está cerrada en un while de espera: el hilo no termina nunca

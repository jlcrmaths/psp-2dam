Problemas de sincronización

PSP · 2º DAM · Apartado 6.4

Objetivo de la clase

  • Resolver cinco problemas con hilos que comparten un objeto
  • Reconocer el patrón que se repite en todos
  • Simular tiempo con Thread.sleep() y azar con Random
  • Esperar a que terminen varios hilos con join()
  • Leer del teclado con Scanner y escribir en un fichero

El patrón de los cinco ejercicios

  1. Hay un objeto compartido (fichero, cinta, lavandería…)
  2. Sus métodos son synchronized
  3. Si el hilo no puede continuar: while (no puedo) wait();
  4. Cuando cambia el estado: notifyAll();
  5. Los hilos solo duermen, llaman al objeto y repiten

Entiende uno y entiendes los cinco.

Herramientas nuevas

  • Thread.sleep(2000): duerme el hilo 2 segundos (2000 milisegundos). Simula que algo tarda
  • new Random().nextInt(3): número al azar entre 0 y 2
  • hilo.join(): «espero aquí hasta que ese hilo termine»
  • new Scanner(System.in).nextInt(): lee un número que escribe el usuario
  • ArrayList<Thread>: una lista que crece sola

Regla: sleep va fuera de synchronized. Si un hilo duerme dentro, los demás no pueden ni entrar a mirar.

Ejercicio 1: lectores y escritores

  • 10 hilos escritores: cada uno escribe su nombre en una línea nueva de un fichero
  • 10 hilos lectores: cada uno cuenta las líneas que hay en ese momento y lo muestra
Escritor 1 ha escrito su nombre
Lector 1 lee: el fichero tiene 1 líneas
…

Proyecto LectoresEscritores

¿Qué puede salir mal?

Si un lector lee mientras un escritor escribe, puede ver datos a medias. Si dos escritores escriben a la vez, las líneas se mezclan.

Solución: el fichero es un objeto compartido y sus métodos son synchronized. Mientras uno trabaja, los demás esperan fuera.

Aquí no hace falta wait(): nadie tiene que esperar a que ocurra nada concreto. Solo no pisarse.

Solución: el fichero

    public synchronized void escribir(String nombre) {
        try {
            FileWriter fw = new FileWriter(ruta, true);
            fw.write(nombre + "\n");
            fw.close();
            System.out.println(nombre + " ha escrito su nombre");
        } catch (IOException e) {
            System.out.println(nombre + " no ha podido escribir");
        }
    }

    public synchronized void contarLineas(String nombre) {
        try {
            int lineas = Files.readAllLines(Path.of(ruta)).size();
            System.out.println(nombre + " lee: el fichero tiene " + lineas + " líneas");
        } catch (IOException e) {
            System.out.println(nombre + " no ha podido leer");
        }
    }

Línea por línea

  • synchronized: un solo hilo a la vez dentro del método. Vale para los dos métodos: un lector tampoco entra si hay un escritor dentro
  • new FileWriter(ruta, true): abre el fichero. El true significa «añadir al final»; sin él borraría lo anterior
  • fw.write(nombre + "\n"): escribe el nombre y un salto de línea
  • fw.close(): cierra el fichero y guarda lo escrito
  • Files.readAllLines(...): lee todo el fichero y devuelve una lista con una entrada por línea; size() dice cuántas
  • try / catch (IOException e): Java obliga a prever que un fichero puede fallar

Crear los 20 hilos


Fichero fichero = new Fichero("escritores.txt");

for (int i = 1; i <= 10; i++) {
    Thread escritor = new Thread(new Escritor(fichero), "Escritor " + i);
    Thread lector = new Thread(new Lector(fichero), "Lector " + i);
    escritor.start();
    lector.start();
}

Un solo Fichero, 20 hilos. Cada vuelta del for lanza un escritor y un lector.

Ejercicio 2: fábrica de piezas

  • 3 máquinas ponen piezas en una cinta de capacidad 5. Una pieza cada 1–3 s
  • 1 empaquetadora retira una pieza cada 2 s
  • Cinta llena: las máquinas esperan. Cinta vacía: la empaquetadora espera
  • Acaba al fabricar 50 piezas. Se muestra «Fábrica cerrada»

Proyecto FabricaPiezas

Cómo pensarlo

  • Es el pintor y el vendedor otra vez, pero con tres productores → notifyAll()
  • El límite de 50 es de todas las máquinas juntas → el contador está en la Cinta, no en cada máquina
  • ¿Cómo sabe una máquina que debe parar? → poner() devuelve false

Solución: la cinta

    public synchronized boolean poner() {
        while (piezas == 5 && fabricadas < 50) {
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        if (fabricadas == 50) {
            return false;
        }
        piezas++;
        fabricadas++;
        System.out.println(Thread.currentThread().getName() + ": pone la pieza " + fabricadas + ". Cinta: " + piezas + "/5");
        notifyAll();
        return true;
    }

Línea por línea

  • while (piezas == 5 && fabricadas < 50): espera si la cinta está llena y aún faltan piezas. Si ya se hicieron 50 no tiene sentido esperar
  • if (fabricadas == 50) return false;: ya no hacen falta más piezas. La máquina recibe false y termina
  • piezas++; fabricadas++;: ++ suma uno. Una pieza más en la cinta y una más fabricada
  • notifyAll(): despierta a todos. La empaquetadora ya puede retirar; las máquinas comprueban si hay hueco

retirar() es igual al revés: espera mientras piezas == 0, resta una y avisa.

La máquina: sleep y Random

    public void run() {
        Random azar = new Random();
        boolean seguir = true;
        while (seguir) {
            try {
                Thread.sleep((1 + azar.nextInt(3)) * 1000);
            } catch (InterruptedException e) {
            }
            seguir = cinta.poner();
        }
    }
  • azar.nextInt(3) da 0, 1 o 2. Con 1 + … sale 1, 2 o 3
  • Se multiplica por 1000: sleep trabaja en milisegundos

Esperar a que acaben todos: join


m1.start();
m2.start();
m3.start();
empaquetador.start();

m1.join();
m2.join();
m3.join();
empaquetador.join();

System.out.println("Fábrica cerrada");
  • join(): «espero a que este hilo termine»
  • Sin los join(), «Fábrica cerrada» saldría al principio, porque main no espera
  • main declara throws InterruptedException para no escribir un try/catch en cada join

Ejercicio 3: lavandería CleanFast

  • 4 lavadoras. Cada cliente lava de 5 a 10 segundos y paga 3 €
  • Sin lavadora libre, el cliente espera. Solo cuenta como atendido cuando consigue una
  • Menú: 1) llegan clientes, 2) estado, 3) cerrar (espera a que terminen todos)

Proyecto Lavanderia

Cómo pensarlo

  • ¿Hace falta una clase por lavadora? No: solo importa cuántas hay libres.
  • Es el almacén de un cuadro, pero con 4 huecos en vez de 1
  • ¿Dónde cuento al cliente como atendido? Justo después del while, cuando ya tiene lavadora.

Solución: la lavandería

    public synchronized void entrar() {
        String nombre = Thread.currentThread().getName();
        if (libres == 0) {
            System.out.println(nombre + " espera en la cola");
        }
        while (libres == 0) {
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        libres--;
        atendidos++;
        System.out.println(nombre + " paga 3€ y empieza a lavar");
    }

    public synchronized void salir() {
        libres++;
        System.out.println(Thread.currentThread().getName() + " termina y deja libre una lavadora");
        notifyAll();
    }

El cliente

  • lavanderia.entrar(): espera si no hay lavadora y coge una
  • Thread.sleep(…): lava entre 5 y 10 segundos. Fuera de synchronized: las otras lavadoras siguen trabajando
  • lavanderia.salir(): deja la lavadora libre y avisa con notifyAll()

Se usa notifyAll() porque pueden esperar varios clientes y todos buscan lo mismo: el que llegue primero a la lavadora, la coge.

El menú


Scanner teclado = new Scanner(System.in);
ArrayList<Thread> clientes = new ArrayList<>();

int opcion = teclado.nextInt();
switch (opcion) {
    case 1:
        int cuantos = teclado.nextInt();
        for (int i = 0; i < cuantos; i++) {
            Thread c = new Thread(new Cliente(lavanderia), "Cliente " + siguiente);
            clientes.add(c);
            c.start();
        }
        break;
    case 2:
        lavanderia.mostrarEstado();
        break;
    case 3:
        abierta = false;
        break;
}

Línea por línea

  • Scanner: lee lo que escribe el usuario. nextInt() lee un número
  • ArrayList<Thread>: una lista de hilos que crece sola. Aquí no sabemos cuántos clientes llegarán, así que un array de tamaño fijo no sirve
  • switch: elige qué hacer según la opción. Cada case acaba en break
  • Cerrar = salir del bucle, y después esperar a todos los clientes:

for (Thread t : clientes) {
    t.join();
}

«Para cada hilo t de la lista, espera a que termine.»

Ejercicio 4: panadería self-service

  • 20 barras al abrir. Cada segundo el panadero mira: si quedan menos de 10, hornea 20 (tarda 20 s)
  • Cada cliente pide de 1 a 10 barras. Si no hay suficientes, espera
  • Primera barra 1 €, las demás 0,75 €
  • Menú: 1) grupo de clientes, 2) estado, 3) cerrar
  • Al cerrar: el panadero se lleva lo que queda y hornea un último lote

Proyecto Panaderia

Cómo pensarlo

  • ¿Quién comparte qué? Panadero y clientes comparten el Mostrador.
  • Hornear tarda 20 s. ¿Dentro de synchronized? No: los clientes no podrían comprar mientras tanto.
  • ¿Cuándo se cierra? Cuando todos los clientes han terminado. Algunos aún esperan pan: el panadero tiene que seguir horneando.

Solución: el mostrador

    private int barras = 20;
    private int horneadas = 20;
    private int vendidas = 0;
    private double dinero = 0;
    private boolean cerrando = false;

    public synchronized void comprar(int cuantas) {
        String nombre = Thread.currentThread().getName();
        if (barras < cuantas) {
            System.out.println(nombre + " quiere " + cuantas + " barras y espera: hay " + barras);
        }
        while (barras < cuantas) {
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        barras = barras - cuantas;
        vendidas = vendidas + cuantas;
        double precio = 1 + 0.75 * (cuantas - 1);
        dinero = dinero + precio;
        System.out.println(nombre + " compró " + cuantas + " barras por " + precio + "€. Barras restantes: " + barras);
    }

Línea por línea

  • double dinero: double es un número con decimales
  • while (barras < cuantas): el cliente espera hasta que haya tantas como pide, no solo «alguna»
  • 1 + 0.75 * (cuantas - 1): la primera barra 1 €, las demás 0,75 €. Con 3 barras: 1 + 0,75 × 2 = 2,50 €
  • reponer(20): suma las barras y llama a notifyAll(). Los clientes dormidos vuelven a mirar si ya hay suficientes

El panadero

    public void run() {
        while (!mostrador.estaCerrando()) {
            dormir(1000);
            if (!mostrador.estaCerrando() && mostrador.hacenFalta()) {
                hornear();
            }
        }
        mostrador.vaciar();
        hornear();
    }

    private void hornear() {
        System.out.println("Panadero horneando 20 barras...");
        dormir(20000);
        mostrador.reponer(20);
    }

    private void dormir(int milisegundos) {
        try {
            Thread.sleep(milisegundos);
        } catch (InterruptedException e) {
        }
    }
  • dormir() y hornear() son métodos de la propia clase: evitan repetir las mismas líneas

Cerrar la panadería

  1. Salir del menú. No se aceptan más clientes
  2. join() a todos los clientes: los que esperan pan se atienden
  3. mostrador.cerrar(): avisa al panadero
  4. El panadero sale de su bucle, se lleva lo que queda y hornea el último lote
  5. join() al panadero y resumen final

El orden importa. Si se avisara al panadero antes, vaciaría el mostrador y los clientes que esperan se quedarían colgados.

Ejercicio 5: sala de partida de stream

  • Jugadores: solo uno en la sala. Los demás esperan en cola
  • Espectadores: entran todos los que quieran, pero solo si hay partida. Si no, esperan
  • Cuando la partida acaba, los espectadores salen. Para ver la siguiente deben entrar de nuevo

Proyecto SalaStream

Dos grupos esperando cosas distintas

  • El jugador espera a que no haya partida
  • El espectador espera a que sí haya partida

Los dos esperan sobre el mismo objeto, Sala. Por eso notifyAll(): cada uno se despierta, mira su condición y, si no es su momento, se vuelve a dormir.

El truco: el número de partida

Un espectador debe irse cuando acaba su partida, aunque otro jugador ya haya empezado la siguiente.

Si solo mirara «¿hay partida?», se quedaría a la siguiente sin darse cuenta.

Solución: al entrar, apunta el número de la partida. Se queda mientras jugando && partida == mi número.

Solución: la sala

    private boolean jugando = false;
    private int partida = 0;
    private int espectadores = 0;
    private boolean cerrada = false;

    public synchronized void empezarPartida() {
        String nombre = Thread.currentThread().getName();
        if (jugando) {
            System.out.println(nombre + " espera en la cola: la sala está ocupada");
        }
        while (jugando) {
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        jugando = true;
        partida++;
        System.out.println(nombre + " empieza la partida " + partida);
        notifyAll();
    }

Los espectadores

    public synchronized int entrarEspectador() {
        String nombre = Thread.currentThread().getName();
        if (!jugando && !cerrada) {
            System.out.println(nombre + " espera a que empiece una partida");
        }
        while (!jugando && !cerrada) {
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        if (!jugando) {
            return 0;
        }
        espectadores++;
        System.out.println(nombre + " entra a ver la partida " + partida + " (espectadores: " + espectadores + ")");
        return partida;
    }

    public synchronized void ver(int numeroPartida) {
        while (jugando && partida == numeroPartida) {
            try {
                wait();
            } catch (InterruptedException e) {
            }
        }
        espectadores--;
        System.out.println(Thread.currentThread().getName() + " sale de la sala (espectadores: " + espectadores + ")");
    }
  • entrarEspectador() devuelve el número de partida que va a ver (o 0 si ya no habrá más)
  • ver(n) espera mientras esa partida siga en marcha, y entonces sale
  • cerrar() lo llama main al acabar los jugadores: libera a los espectadores que esperaban una partida que ya no llegará

¿Qué sale en pantalla?

Jugador 1 empieza la partida 1
Jugador 2 espera en la cola: la sala está ocupada
Espectador 6 entra a ver la partida 1 (espectadores: 1)
Jugador 1 termina la partida 1 y sale de la sala
Jugador 2 empieza la partida 2
Espectador 6 sale de la sala (espectadores: 0)
…

Cambia en cada ejecución: quién llega primero y quién entra de la cola no está fijado.

Errores típicos

  • Thread.sleep() dentro de un método synchronized: nadie más puede avanzar
  • notify() en vez de notifyAll(): a veces funciona y a veces se cuelga
  • if en vez de while alrededor de wait()
  • Un objeto compartido por hilo: ya no se comparte nada
  • Olvidar los join(): el mensaje final sale al principio
  • Contar el límite en cada hilo en vez de en el objeto compartido

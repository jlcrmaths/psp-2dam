Prioridades de los hilos

PSP · 2º DAM · Apartado 6.2

Objetivo de la clase

  • Saber qué es la prioridad de un hilo
  • Cambiarla con setPriority() y leerla con getPriority()
  • Conocer Thread.yield()
  • Comprobar que la prioridad no garantiza el orden

¿Qué es la prioridad?

Cada hilo tiene un número del 1 al 10: su prioridad.

Con muchos hilos y pocos núcleos, el planificador decide quién se ejecuta. La prioridad es un consejo para esa decisión: más número, más ganas de que le toque.

Tres valores ya preparados

  • Thread.MIN_PRIORITY: vale 1
  • Thread.NORM_PRIORITY: vale 5 (la normal)
  • Thread.MAX_PRIORITY: vale 10

Un hilo nuevo hereda la prioridad del hilo que lo crea. Como main tiene 5, los hilos nacen con 5.

Dos métodos


h1.setPriority(Thread.MAX_PRIORITY);
int p = h1.getPriority();
  • El método setPriority(...) de la clase Thread: cambia la prioridad. Se llama antes de start()
  • El método getPriority() de la clase Thread: devuelve el número

Lo nuevo de hoy

Constantes

Thread.MIN_PRIORITY, NORM_PRIORITY y MAX_PRIORITY: nombres para los números 1, 5 y 10.

Método

setPriority(n) de la clase Thread: fija la prioridad antes de start(). getPriority() la devuelve.

Método

yield() de la clase Thread: el hilo ofrece su turno al planificador. Solo es una sugerencia.

Concepto

Planificador: la parte del sistema que decide qué hilo usa el núcleo en cada momento.

Ejercicio 1: quince hilos

La tarea: unir 20000 letras "A" en una cadena. Todos los hilos hacen la misma.

  • 5 hilos con prioridad mínima (1)
  • 5 hilos con prioridad normal (5)
  • 5 hilos con prioridad máxima (10)

Al terminar, cada hilo muestra su nombre y su prioridad:

Hilos en marcha, espera...
Máximo 3 (prioridad 10) termina
Normal 1 (prioridad 5) termina
…

Proyecto PrioridadesHilos

Cómo pensarlo

  • ¿Cuántas clases con run()? Una: Tarea. Los quince hilos hacen lo mismo.
  • ¿Dónde se pone la prioridad? No en la tarea: en cada Thread, con setPriority().
  • ¿Cómo guardo quince hilos? Tres arrays de cinco, como en 6.1.

La clase Tarea

public class Tarea implements Runnable {

    @Override
    public void run() {
        String cadena = "";
        for (int i = 0; i < 200000; i++) {
            cadena += "A";
            Thread.yield();
        }
        System.out.println(Thread.currentThread().getName() + " (prioridad " + Thread.currentThread().getPriority() + ") termina");
    }
}

Tarea, línea por línea

  • public class Tarea implements Runnable
    Una tarea que puede ejecutarse en un hilo.
  • String cadena = "";
    Una cadena vacía.
  • for (int i = 0; i < 20000; i++)
    20000 vueltas.
  • cadena += "A";
    Añade una "A". Es lento a propósito: copiar la cadena cada vez hace la tarea pesada.
  • Thread.yield();
    El método yield() de la clase Thread sugiere que otro hilo pase. Se repite en cada vuelta.
  • getName() y getPriority()
    Métodos de la clase Thread. Al final, el hilo dice su nombre y su prioridad.

Principal: crear los hilos


Thread[] minimos = new Thread[5];
Thread[] normales = new Thread[5];
Thread[] maximos = new Thread[5];

for (int i = 0; i < 5; i++) {
    minimos[i] = new Thread(new Tarea(), "Mínimo " + (i + 1));
    normales[i] = new Thread(new Tarea(), "Normal " + (i + 1));
    maximos[i] = new Thread(new Tarea(), "Máximo " + (i + 1));
    minimos[i].setPriority(Thread.MIN_PRIORITY);
    maximos[i].setPriority(Thread.MAX_PRIORITY);
}

Principal: línea por línea

  • Tres arrays de cinco Thread, uno por prioridad.
  • El for da cinco vueltas. En cada una crea tres hilos con la misma clase Tarea y nombres distintos.
  • "Mínimo " + (i + 1): el paréntesis hace que sume 1 antes de unir el texto (Mínimo 1, no Mínimo 01).
  • Los mínimos y los máximos llaman al método setPriority() de la clase Thread. Los normales no: ya tienen 5.

Principal: arrancar


System.out.println("Hilos en marcha, espera...");

for (int i = 0; i < 5; i++) {
    minimos[i].start();
    normales[i].start();
    maximos[i].start();
}

Se arrancan intercalados, para que ninguna prioridad salga con ventaja por empezar antes.

¿Qué sale en pantalla?

Hilos en marcha, espera...
Mínimo 5 (prioridad 1) termina
Máximo 1 (prioridad 10) termina
Normal 5 (prioridad 5) termina
…

Los hilos de prioridad 10 no siempre terminan los primeros. A veces ni siquiera terminan antes que los de prioridad 1.

¿Por qué?

  • Java no gestiona las prioridades: se las pasa al sistema operativo.
  • Cada sistema las trata a su manera, y algunos casi las ignoran.
  • Con varios núcleos, todos los hilos avanzan a la vez y la prioridad pesa poco.

Para obligar a un orden no uses prioridades: usa join() o wait()/notify().

Resumen

  • La prioridad de un hilo es un número del 1 al 10
  • MIN_PRIORITY = 1, NORM_PRIORITY = 5, MAX_PRIORITY = 10
  • Métodos de la clase Thread: setPriority() la cambia (antes de start()) y getPriority() la lee
  • Un hilo hereda la prioridad del hilo que lo crea
  • El método yield() de la clase Thread es solo una sugerencia
  • La prioridad no garantiza el orden: no se usa para sincronizar

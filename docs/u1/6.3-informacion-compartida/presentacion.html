Información compartida entre hilos

PSP · 2º DAM · Apartado 6.3

Objetivo de la clase

  • Ver qué pasa cuando varios hilos usan el mismo objeto
  • Entender la condición de carrera
  • Comprobar que lo que parece correcto puede no serlo
  • Saber por qué hace falta sincronizar

Hasta ahora, cada hilo iba a lo suyo

En 6.1 y 6.2 cada hilo hacía su trabajo sin tocar lo de los demás.

Ahora varios hilos van a compartir un objeto: todos leen y cambian el mismo dato.

El problema de los jardines

Un jardín tiene 100 personas. Entran 10 y salen 10, todas a la vez.

Al final debería haber 100 otra vez.

¿Saldrá siempre 100?

Ejercicio 1: los jardines

20 hilos: 10 entran (suman 1) y 10 salen (restan 1). Al acabar todos, main muestra la cuenta.

Personas en el jardín: 100

Ejecútalo varias veces y apunta qué sale.

Proyecto ProblemaJardines

Cómo pensarlo

  • ¿Qué comparten los hilos? El jardín: un solo objeto RecursoJardin.
  • ¿Cuántas clases de hilo? Dos: EntraJardin y SaleJardin.
  • ¿Cómo espera main a los 20? Con el método join() de la clase Thread en cada uno.

El jardín: RecursoJardin

public class RecursoJardin {

    private int cuenta;

    public RecursoJardin() {
        cuenta = 100;
    }

    public int getCuenta() {
        return cuenta;
    }

    public void incrementaCuenta() {
        System.out.println("hilo " + Thread.currentThread().getName() + " ----- Entra en Jardín");
        cuenta++;
        System.out.println(cuenta + " en jardín");
    }

    public void decrementaCuenta() {
        System.out.println("hilo " + Thread.currentThread().getName() + " ----- Sale de Jardín");
        cuenta--;
        System.out.println(cuenta + " en jardín");
    }
}

RecursoJardin, línea por línea

  • private int cuenta;
    El número de personas. Es el dato que comparten los 20 hilos.
  • cuenta = 100;
    En el constructor, empieza con 100 personas.
  • getCuenta()
    Método de la clase RecursoJardin. Devuelve la cuenta, para mostrarla al final.
  • System.out.println("hilo " + ...)
    Muestra qué hilo entra. El método getName() de la clase Thread da su nombre, y currentThread() dice cuál es el hilo que ejecuta esta línea.
  • cuenta++;
    Suma 1 a la cuenta. cuenta--; resta 1 en el método que sale.
  • System.out.println(cuenta + " en jardín")
    Muestra cuántas personas hay después del cambio.

Los hilos y Principal


RecursoJardin jardin = new RecursoJardin();
ArrayList<Thread> lista = new ArrayList<>();

for (int i = 1; i <= 10; i++) {
    lista.add(new Thread(new EntraJardin(jardin), "Entra" + i));
    lista.add(new Thread(new SaleJardin(jardin), "Sale" + i));
}

for (Thread t : lista) {
    t.start();
}

for (Thread t : lista) {
    t.join();
}

Principal, línea por línea

  • Se crea un solo jardín. Los 20 hilos reciben ese mismo objeto.
  • El primer for crea los hilos y los guarda en la lista con el método add() de la clase ArrayList: uno que entra y otro que sale, diez veces.
  • El segundo recorre la lista y arranca cada hilo con el método start() de la clase Thread.
  • El tercero llama al método join() de la clase Thread en cada uno: main espera a que acaben los 20 antes de mostrar la cuenta.

Una idea para recordarlo

Una pizarra con un número escrito. Veinte personas lo leen, calculan en su cabeza y lo borran para escribir el nuevo.

Si dos leen el mismo número a la vez, las dos escribirán el mismo resultado. Una de las dos se pierde.

Sumar 1 son tres pasos

Aunque se escriba en una línea, para el ordenador son tres pasos:

  1. Leer la cuenta
  2. Calcular el nuevo valor
  3. Guardar la cuenta

Otro hilo puede colarse entre dos pasos.

Condición de carrera

Cuando varios hilos leen y cambian el mismo dato, y el resultado depende de quién llega antes.

Lo peor: el programa no da error. A veces sale bien y a veces mal, y no se puede predecir.

Y ahora la pregunta: ¿cómo evitamos que dos hilos estén a la vez dentro de incrementaCuenta? Es el ejercicio 2.

Ejercicio 2: jardines sincronizados

Lo que se pide: el mismo programa, pero con el resultado y el registro siempre correctos.

Personas en el jardín: 100

En todas las ejecuciones, y con cada hilo mostrando su línea seguida de su cuenta. Solo cambia la clase RecursoJardin.

Proyecto JardinesSincronizado

Antes de ver la solución

  • ¿Qué tendría que pasar para que no se cuelen dos hilos?
  • ¿Qué método hay que proteger: solo uno o los dos?
  • ¿Qué pierde el programa si los hilos pasan de uno en uno?

Lo nuevo de hoy

Palabra

synchronized: se escribe en la cabecera de un método. Solo deja entrar a un hilo a la vez; los demás esperan fuera.

Concepto

Cerrojo: cada objeto tiene uno. El hilo que entra en un método synchronized lo coge y lo suelta al salir.

Concepto

Condición de carrera: el resultado depende de qué hilo llega antes. La has visto en el ejercicio 1.

Como una puerta de una sola persona: el que está dentro lee, calcula y guarda sin que nadie se cuele.

El jardín sincronizado

public class RecursoJardin {

    private int cuenta;

    public RecursoJardin() {
        cuenta = 100;
    }

    public int getCuenta() {
        return cuenta;
    }

    public synchronized void incrementaCuenta() {
        System.out.println("hilo " + Thread.currentThread().getName() + " ----- Entra en Jardín");
        cuenta++;
        System.out.println(cuenta + " en jardín");
    }

    public synchronized void decrementaCuenta() {
        System.out.println("hilo " + Thread.currentThread().getName() + " ----- Sale de Jardín");
        cuenta--;
        System.out.println(cuenta + " en jardín");
    }
}

Qué cambia, línea por línea

  • public synchronized void incrementaCuenta()
    Solo un hilo a la vez puede ejecutar este método.
  • public synchronized void decrementaCuenta()
    Lo mismo aquí. Hace falta en los dos: quien entra y quien sale tocan la misma variable.
  • El resto del código no cambia: ni los hilos, ni Principal.

¿Qué sale en pantalla?

hilo Entra1 ----- Entra en Jardín
101 en jardín
hilo Sale1 ----- Sale de Jardín
100 en jardín
…
Personas en el jardín: 100

Ahora cada hilo muestra su línea y su cuenta seguidas, y el resultado es correcto siempre. Los 20 hilos pasan uno detrás de otro por los métodos del jardín.

Sincronizar da un resultado correcto, pero quita la ventaja de hacer varias cosas a la vez.

Resumen

  • Los hilos pueden compartir un objeto: todos reciben la misma referencia
  • Sumar 1 son tres pasos: leer, calcular y guardar
  • Si dos hilos se cuelan entre los pasos, se pierden cambios: condición de carrera
  • El registro sale desordenado y el resultado puede ser incorrecto, aunque a veces salga 100
  • El método join() de la clase Thread hace que main espere a todos antes de mostrar el resultado
  • Se arregla con la palabra synchronized en los métodos del jardín: un solo hilo a la vez
  • Sincronizar da el resultado correcto, pero los hilos pasan de uno en uno por esos métodos
